# (srfi 26) — `cut` and `cute`

Notation for partial application: `cut` builds a procedure from a call with
`<>` marking the argument positions, and `cute` is the same with the
non-slot arguments evaluated once, when the procedure is made rather than when
it is called.  Both are written in Scheme and embedded in the binary.

```scheme
(import (scheme base) (srfi 26))
```

## Syntax

| Form | Arguments | Description |
|---|---|---|
| `cut` | `(cut argument ...)` | Returns a procedure.  Each `<>` becomes one formal parameter, in order; a final `<...>` collects the remaining arguments and applies them with `apply`; every other argument is evaluated **at call time**, inside the returned procedure. |
| `cute` | `(cute argument ...)` | The same, except that the arguments other than `<>` and `<...>` are evaluated once, when `cute` is evaluated, and the returned procedure closes over those values. |

## Notes

* With no `<>` at all, `(cut f x)` is a thunk: `((cut list 1 2))` is `(1 2)`.
* At most eight slots are supported (`<>` or the `<...>` tail), which is the
  pool of names the expansion draws from.
* `cut` is the one to reach for inside a loop that mutates what it mentions;
  `cute` is the one to reach for when the value should be frozen now — it is
  the difference between `(cut list n <>)` and `(cute list n <>)` below.

## Example

```scheme
((cut + 1 <>) 2)                  ; => 3
((cut list <> <>) 1 2)            ; => (1 2)
((cut list <...>) 1 2 3)          ; => (1 2 3)
(map (cut * 2 <>) '(1 2 3))       ; => (2 4 6)
((cut cons <> 2) 1)               ; => (1 . 2)

(let ((n 1))
  (define lazy (cut list n <>))   ; n is read when lazy is called
  (define eager (cute list n <>))
  (set! n 2)
  (list (lazy 3) (eager 3)))      ; => ((2 3) (1 3))
```
